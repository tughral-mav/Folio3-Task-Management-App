# Story 1.4 — Base Schema, Triggers & RLS

**Status:** Done (2026-08-11) — verified by CI schema job
**PRD:** [Epic 1](../requirements/prd.md#epic-1--foundation--infrastructure) · **Architecture:** §3–§6

Seven migrations implementing the full architecture §3 design:

| Migration | Contents |
|---|---|
| `…100000_init` | pgcrypto, `private` schema, 5 enums (ADR-5), `private.app_settings` (allowed_domain) |
| `…100100_tables` | users / tasks / task_updates / notifications / task_activity + constraints, indexes, `updated_at` + `completed_at` (EC-T4) triggers |
| `…100200_auth_provisioning` | ADR-1 domain gate: `handle_new_auth_user` AFTER INSERT on `auth.users` (rejects unverified/non-folio3.com → aborts auth txn; provisions profile atomically), profile sync (EC-A5), identity/role guard (SEC-6) |
| `…100300_fanout` | ADR-4/ADR-8: `notify_user` helper (future preference hook, FR33), task INSERT/UPDATE + task_updates INSERT triggers — consolidated notifications (EC-N6), self-action suppression (EC-N1), RPC suppression GUC |
| `…100400_rls` | ADR-2 helpers (`is_admin`/`is_provisioned`), RLS enabled everywhere, full policy matrix (deny-by-absence for all writes not explicitly allowed), notifications read_at-only guard |
| `…100500_rpcs` | ADR-3 `submit_progress_update` (FOR UPDATE lock, D3 transition subset, EC-T6/P1 validation, no-leak errors) + race-safe `mark_all_notifications_read` (EC-N3) |
| `…100600_realtime` | notifications + tasks in the `supabase_realtime` publication |

Note: the gate trigger is AFTER INSERT (not BEFORE as architecture §4 originally sketched) because `public.users.id` has an FK to `auth.users(id)` — the RAISE still aborts the entire auth transaction. Architecture doc updated accordingly.
