# Story 7.1 — Authorization & RLS Test Suite

**Status:** Review (2026-08-11) — executes in CI schema job
**PRD:** [Epic 7](../requirements/prd.md#epic-7--hardening-verification--deployment) · Tests 10–12, SEC-8

`tests/rls/` (vitest + `pg`, separate config so `npm test` stays Docker-free). Impersonates PostgREST roles via `SET LOCAL ROLE` + `request.jwt.claims` in rolled-back transactions — production-faithful `auth.uid()`. Covers, positive and negative:

- **anon** obtains no rows from any table; cannot insert (Test 3 DB layer)
- **IDOR (Test 10):** member A sees only own tasks; member B's task-by-id returns nothing; admin sees all
- **admin-only (Test 12):** member cannot insert/update/reassign tasks; `created_by` spoofing rejected by WITH CHECK; no DELETE path for anyone (A1)
- **privilege escalation (Test 11):** member cannot change own or others' role (verified unchanged in a second transaction)
- **immutability:** task_updates and task_activity reject UPDATE/DELETE (A3, SEC-17/18); notification content guarded to read_at-only
- **notifications (EC-N2):** own-rows-only read; cannot mark another's read
- **RPC (ADR-3):** assignee submits on own open task; non-assignee rejected (EC-P3); disallowed status rejected (EC-T5); progress on completed task rejected (EC-T6); out-of-range percent rejected (EC-P1)

Wired into the CI schema job (Node + `npm run test:rls`) after schema verification.
