# Story 2.3 — Auto-Provisioning

**Status:** Review (2026-08-11)
**PRD:** [Epic 2](../requirements/prd.md#epic-2--authentication--user-provisioning) · FR3, FR4

Fully DB-side (ADR-1, Story 1.4): first login inserts `public.users` (role `TEAM_MEMBER`) atomically inside the auth transaction; `unique(id)`/`unique(email)` + `ON CONFLICT DO NOTHING` make duplicates impossible (EC-A4); repeat logins preserve role; profile sync trigger refreshes name/avatar (EC-A5). App layer treats a session without a profile as deny (`requireUser` → access-denied). CI seed exercises provisioning + admin promotion procedure.
